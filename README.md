# grisha_helper_bot

Telegram-бот для вакансий Санкт-Петербурга, удалённой работы, домовых чатов, ежедневных сводок групп и финансовых запросов СМИ. Результаты приходят в один настроенный чат владельца.

## Имя проекта и развёртывание

- Telegram: `@grisha_helper_bot`.
- GitHub: `grigra27/grisha_helper_bot`.
- Локальная папка: `~/Dev/grisha_helper_bot`.
- Сервер AMS: `/opt/grisha_helper_bot`; GitHub Actions secret `VPS_PATH` указывает на этот каталог.
- Compose-проект и контейнер: `grisha_helper_bot`.
- Образ: `grisha_helper_bot:latest`.
- Постоянные данные: внешний Docker-том `grisha_helper_bot_appdata`, подключённый к `/data`.
- Сеть Compose: `grisha_helper_bot_default`.

Имя Compose задано явно и не зависит от расположения папки. Том объявлен внешним:
деплой останавливается, если том отсутствует, вместо запуска с новой пустой базой.
При первой установке том нужно подготовить отдельно; при переносе существующей
установки сначала восстановить в него данные и проверить SQLite.

Push в `main` запускает тесты и сборку с развёртыванием на AMS. Workflow также
поддерживает ручной запуск: `build_image=false` использует уже проверенный образ
на сервере без пересборки. Развёртывания выполняются последовательно.

## Возможности

- Читает новые посты из настроенных Telegram-каналов через пользовательскую сессию Telethon.
- Выбирает вакансии Санкт-Петербурга и удалённой работы, исключает названия со стоп-словами, сохраняет ссылки и название компании. Поддерживает посты с городскими блоками и отдельные карточки [Perforum Jobs](https://t.me/Perforum_jobs) со ссылкой на сайт.
- Отправляет вакансии автоматически **ежедневно в 13:00 по Москве (10:00 UTC)**, включая выходные, либо по команде.
- По ручной команде читает новые сообщения из настроенных домовых чатов и делает краткую сводку отдельно по каждому дому.
- Собирает обсуждения групп через Groq и отправляет отдельные ежедневные тематические сводки: `@vakifbank_tr` и `@InteractiveBrokersRUS`, **21:00 по Москве**.
- Проверяет `@Pressfeed_queries`, `@partyzan499` и `@photodrive` раз в час с **09:00 до 21:00 МСК**, включая выходные. Groq отбирает запросы финансовому эксперту; общая история отправок защищает от повторов между источниками.
- Хранит курсоры Telegram-источников и состояние паузы в SQLite.

Вакансии разбираются кодом, без LLM. **Groq нужен для сводок домовых чатов, групп и отбора запросов СМИ**: сообщения передаются настроенному OpenAI-compatible API. По умолчанию используется Groq и модель `llama-3.3-70b-versatile`.

## Команды

Доступ ограничен одним `TELEGRAM_CHAT_ID`. При старте бот публикует меню команд для этого чата.

| Команда | Действие |
| --- | --- |
| `/help`, `/start` | Список команд |
| `/status` | Состояние, источники и расписание |
| `/jobs_spb_now` | Собрать вакансии СПб и удалённой работы сейчас |
| `/house_chats_now` | Подготовить сводку домовых чатов сейчас |
| `/group_digest_now` | Подготовить отдельные сводки настроенных групп сейчас |
| `/press_now` | Проверить новые финансовые запросы СМИ сейчас, независимо от времени суток |
| `/pause` | Приостановить автоматическую отправку вакансий |
| `/resume` | Возобновить автоматическую отправку вакансий |

Пауза относится только к автоматическим вакансиям; ручные команды, ежедневные сводки групп и мониторинг СМИ продолжают работать. У домовых чатов собственного расписания нет.

## Настройка

Docker Compose читает переменные из `.env` в корне проекта. Пример структуры — `.env.example`.

Обязательные данные бота:

```env
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=123456789
```

Для чтения Telegram-источников включите пользовательскую сессию:

```env
TELEGRAM_USER_ENABLED=1
TELEGRAM_USER_API_ID=123456
TELEGRAM_USER_API_HASH=your_telegram_api_hash
TELEGRAM_USER_SESSION=your_authorized_telethon_string_session

TELEGRAM_SOURCE_CHANNELS=@Perforum_jobs
TELEGRAM_SOURCE_FETCH_LIMIT=150
TELEGRAM_HOUSE_CHATS=Дом 1=@house_chat_1;Дом 2=-1001234567890
TELEGRAM_GROUP_DIGEST_CHATS=@vakifbank_tr,@InteractiveBrokersRUS
TELEGRAM_GROUP_DIGEST_TIME=21:00
TELEGRAM_PRESS_CHANNELS=@Pressfeed_queries,@partyzan499,@photodrive
TELEGRAM_PRESS_POLL_MINUTES=60
TELEGRAM_PRESS_ACTIVE_HOURS=09:00-21:00
```

При `TELEGRAM_USER_ENABLED=1` обязательны API ID, API hash и авторизованная `StringSession`, а также хотя бы один источник: канал вакансий, домовой чат, группа для ежедневной сводки или канал запросов СМИ. Можно настроить только один вид источника. Пользовательский аккаунт Telegram должен иметь доступ к выбранным источникам. При `TELEGRAM_USER_ENABLED=0` чтение источников отключено. Пустые `TELEGRAM_GROUP_DIGEST_CHATS` и `TELEGRAM_GROUP_DIGEST_CHAT` отключают сводки групп. Пустые `TELEGRAM_PRESS_CHANNELS` и `TELEGRAM_PRESS_CHANNEL` отключают мониторинг СМИ.

Для нового источника без сохранённого курсора значение `TELEGRAM_SOURCE_FETCH_LIMIT=150` означает первый просмотр **последних 150 постов**, а не всего архива. После доставки первого отчёта следующие запуски выбирают до 150 новых постов, начиная с самого старого ещё не обработанного. Каналы можно перечислять через запятую; у каждого свой курсор. Изменение списка источников не сбрасывает курсоры других каналов или домовых чатов.

Для домовых чатов, сводок групп или мониторинга СМИ дополнительно требуется ключ LLM:

```env
LLM_API_KEY=your_groq_api_key
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=llama-3.3-70b-versatile
```

Если настроены только вакансии, ключ LLM не нужен. Поддерживаются прежние альтернативные имена: `GROQ_API_KEY` или `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`. Основные `LLM_*` имеют приоритет.

Остальные настройки:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `TZ` | `Europe/Moscow` | Часовой пояс приложения; автоматические вакансии закреплены за 10:00 UTC |
| `TELEGRAM_SOURCE_FETCH_LIMIT` | `80` | Лимит сообщений на источник за запуск; для настройки Perforum выше явно задано `150`. Для вакансий верхний предел — 300 постов на канал |
| `TELEGRAM_VACANCY_BANNED_WORDS` | `врач,водитель,агент,терапевт,диспетчер` | Стоп-слова в названии вакансии, без учёта регистра, по вхождению |
| `MAX_CHARS_PER_HOUSE_CHAT_BATCH` | `3000` | Целевой объём текста одного домового чата для LLM; при переполнении остаются более свежие сообщения |
| `SUMMARY_MAX_OUTPUT_TOKENS` | `220` | Лимит ответа LLM для сводки одного дома |
| `TELEGRAM_GROUP_DIGEST_CHAT` | пусто | Совместимость с прежней настройкой одной группы |
| `TELEGRAM_GROUP_DIGEST_CHATS` | пусто | Группы через запятую; имеет приоритет над одиночной настройкой |
| `TELEGRAM_GROUP_DIGEST_TIME` | `21:00` | Время ежедневной сводки группы в формате `HH:MM`, всегда по Москве независимо от `TZ` |
| `TELEGRAM_PRESS_CHANNELS` | пусто | Каналы запросов СМИ через запятую; имеет приоритет над одиночным источником |
| `TELEGRAM_PRESS_CHANNEL` | пусто | Прежний одиночный источник; используется, если список не задан |
| `TELEGRAM_PRESS_POLL_MINUTES` | `60` | Интервал проверок: 5, 10, 15, 20, 30 или 60 минут |
| `TELEGRAM_PRESS_ACTIVE_HOURS` | `09:00-21:00` | Окно автоматических проверок в МСК, границы включены; `00:00-23:59` для круглосуточного режима |
| `LOG_LEVEL` | `INFO` | Уровень журналирования |

Токен бота, пользовательская сессия Telegram и API-ключи — секреты. Не добавляйте `.env` в Git и не копируйте значения в отчёты.

## Запуск

```bash
docker compose up -d --build
```

Проверка состояния и журналов:

```bash
docker compose ps
docker compose logs --tail=100 app
```

Затем проверьте `/status`. Ручные `/jobs_spb_now`, `/house_chats_now`, `/group_digest_now` и `/press_now` выполняют реальную обработку. Курсоры вакансий и отдельной группы сохраняются после отправки всех частей основного отчёта; домовой курсор продвигается после успешного формирования сводки соответствующего дома.

Состояние хранится в volume `appdata`, файл `/data/state.db` внутри контейнера. Обычное пересоздание контейнера сохраняет курсоры и паузу. При обновлении не удаляйте этот volume. При запуске без Docker каталог `/data` должен быть доступен приложению для записи.

## Формат и обработка источников

Вакансии выводятся блоками по каналу и посту: компания, название вакансии, ссылка. Внизу отдельно выводится «удаленная работа». Отчёт содержит число просмотренных постов, обнаруженных и выбранных вакансий по каждому каналу.

Для обычных постов `app/city_extract.py` учитывает городские блоки и ссылки в Telegram entities. Для карточек Perforum модуль `app/perforum_jobs.py` извлекает прямые и скрытые ссылки `perforum.io/jobs/<номер>` и читает публичную страницу вакансии. Название, компания и срок действия берутся из JSON-LD `JobPosting`, город и формат работы — из полей карточки `Location` и `Arrangement`; при отсутствии `Location` город берётся из `jobLocation` в JSON-LD. Отсутствующие сведения не выдумываются; явная удалёнка может не иметь указанного города. Поэтому отсутствие города в коротком Telegram-анонсе не исключает подходящую вакансию.

Фильтры остаются прежними: **Санкт-Петербург или явно доступная удалённая работа**, плюс стоп-слова в названии. Московский гибрид не считается удалёнкой. В разметке Perforum значение `TELECOMMUTE` встречается и у гибрида, поэтому само по себе оно не даёт права включить вакансию в удалённый блок; нужно явное `Remote` или `Remote as option` в формате работы. Подходящие под обе категории карточки выводятся в удалённом блоке. Ни чтение карточек, ни отбор вакансий не используют LLM.

Ссылки одной вакансии с разными tracking-параметрами приводятся к каноническому URL и не дублируются **внутри одного запуска**, включая повторы постов. Постоянного реестра уже показанных вакансий нет: новый пост с той же вакансией в другом запуске может снова попасть в отчёт.

Удалённые страницы (404/410), вакансии с истёкшим `validThrough` и карточки с явным баннером закрытия пропускаются. Баннер закрытия имеет приоритет: на сайте у закрытой вакансии иногда остаётся будущая дата `validThrough`. Старая дата публикации сама по себе не означает архив: вакансия может быть продлена. Временный сетевой отказ, ограничение сайта или ошибка чтения карточки прерывают сбор без продвижения курсоров вакансий; следующий запуск повторно попытается обработать новые посты.

Курсоры вакансий записываются только после доставки **всех частей основного отчёта** в Telegram. Если отправка оборвалась посередине, следующий запуск может повторить уже доставленное начало: подтверждения доставки по отдельной вакансии и гарантии однократной отправки нет.

Домовые чаты задаются парами `Название дома=чат` через `;`. Для каждого дома возвращается краткая строка по новым сообщениям. Ошибка одного чата не прерывает остальные; его курсор не продвигается при неудачном получении сводки. Длинный отчёт делится на сообщения под лимит Telegram.

Лимит числа сообщений за запуск относится к вакансиям и домовым чатам. Сервис хранит курсоры источников, а не полный архив сообщений, постоянную историю URL вакансий или подтверждения доставки каждого пункта отчёта.

## Ежедневные сводки групп

Каждая группа из `TELEGRAM_GROUP_DIGEST_CHATS` обрабатывается отдельно от остальных источников. Прежняя одиночная настройка `TELEGRAM_GROUP_DIGEST_CHAT` поддерживается как fallback. Имена отчётов берутся из Telegram, курсоры остаются привязаны к ID группы; добавление группы не сбрасывает Vakif. Ошибка одной группы не мешает доставке остальных. Первый запуск охватывает последние 24 часа; следующие — все новые доступные сообщения после последней успешно доставленной сводки. Если запуск пропущен или завершился ошибкой, накопившиеся сообщения остаются для следующей попытки. Лимита в 150 сообщений у этой сводки нет.

Тексты и подписи к медиа обрабатываются без обрезания, при необходимости по частям. Перед передачей в Groq распознаваемые реквизиты, телефоны, email и коды доступа маскируются. Из промежуточных результатов собирается итог по темам: что обсуждали, какие решения и вопросы прозвучали, со ссылками на исходные сообщения. Нетекстовые сообщения учитываются отдельно; аудио и видео не расшифровываются. Полнота относится к доступным сообщениям и их тексту, а не к недоступному или удалённому содержимому.

На время запуска фиксируется верхняя граница сообщений: появившиеся позже попадут в следующую сводку. Ручной и автоматический запуск используют общий lock на чтение, формирование, доставку и сохранение курсора. Cursor сохраняется только после доставки всех частей отчёта. При сбое посередине доставки начало отчёта может повториться при следующей попытке.

## Мониторинг запросов СМИ

Каждый час в настроенном окне проверяются новые посты: в 09:00, 10:00 и далее до 21:00 МСК включительно. Первый запуск охватывает последние 24 часа, затем читается весь накопившийся остаток после курсора. Проверки вне окна не выполняют чтение или LLM-вызовы; вечерние посты остаются для утренней проверки.

В Pressfeed один пост содержит несколько запросов: они выделяются по отдельным ссылкам `pressfeed.ru/query/<id>`, включая скрытые Telegram entities. В смешанных лентах `@partyzan499` и `@photodrive` Groq сначала выделяет конкретные вопросы, для которых редакция ищет эксперта. Из большого списка берутся только подходящие пункты. Поиск героя с личной историей, самопрезентация эксперта, PR-знакомства, реклама, платные размещения, вакансии и мероприятия отбрасываются.

Затем Groq проверяет прямую связь самого вопроса с четырьмя направлениями: фондовый рынок, страхование, управление активами и лизинг. Общая макроэкономика, инфляция, подорожание товаров, сборы, обычные кредиты и выплаты пенсионных накоплений сами по себе не подходят. Упоминания банка или страховщика в другом месте поста недостаточно. Длинный текст делится без обрезки, ответы модели проверяются на полноту.

Для смешанных лент обязательны подтверждённый исходным текстом автор или редакция и способ ответить: контакт либо связанная ссылка Pressfeed. Просроченные и противоречивые сроки отклоняются. Относительные даты считаются от публикации, а у пересылок — от исходного сообщения. Без срока допускаются только запросы не старше 24 часов. Названия СМИ, контакты и сроки не выдумываются; если название издания отсутствует, карточка сообщает об этом.

Подходящий запрос приходит отдельной карточкой: конкретный вопрос, СМИ или автор, контакт и срок, причина отбора, ссылка на запрос при наличии и исходный пост. Карточки Pressfeed сохраняют дату из подборки в исходной формулировке. Авторизация в Pressfeed, ответы журналистам и получение полного текста запроса с сайта автоматически не выполняются.

История отправок общая для всех источников, включая прежние уведомления Pressfeed. Для связанных запросов используется каноническая ссылка без tracking-параметров, для свободного текста — нормализованный вопрос, контакт и срок. Одинаковые перепечатки также распознаются до вызова модели. Это защищает от копий, но не гарантирует распознавание полностью переписанного запроса без общей ссылки. Каждая полностью доставленная карточка фиксируется отдельно: при сбое следующей карточки успешные не повторяются. У каждого канала свой курсор; ошибка одного источника не останавливает остальные. Частично отправленная длинная карточка может повториться после сбоя. Медиа без подписи не распознаются. Если подходящих запросов нет, автоматическая проверка не отправляет сообщение. Ручная `/press_now` в этом случае отвечает коротким подтверждением.

## Проверки и диагностика

После установки зависимостей из `app/requirements.txt`:

```bash
python -m unittest discover -s tests -v
```

- При отсутствии автоматических вакансий проверьте `/status`, состояние паузы и запуск в 13:00 по Москве.
- При ошибках авторизации проверьте пользовательскую сессию Telethon и доступ аккаунта к каналу или чату.
- При ошибках домовых сводок проверьте `LLM_API_KEY`, адрес API, модель и доступность провайдера.
- При отсутствии выбранных вакансий проверьте формат исходных постов, ссылки, город, формат работы и стоп-слова. Для Perforum дополнительно проверьте доступность публичных карточек и срок действия вакансии; один `Hybrid` не проходит фильтр удалённой работы.
